# Where AI was used

This file records how AI tools were used to build this MVP, as the submission guidelines ask.
The full write-up is in the separate AI Workflow document (PDF).

## Tools

| Tool | Used for |
| --- | --- |
| Claude (Anthropic), in claude.ai | PRD drafting, UX designs, writing this codebase, tests, README |
| Claude API (`claude-haiku-5-5`) | Inside the app: writes the daily brief when an API key is added |

## What AI generated

- All source code in `src/`, the tests, the CSS and this README were generated by Claude from the PRD and the UX designs.
- The mock data in `src/data/mockData.json` was generated by Claude and is invented. Scores were set to match the PRD's worked example and the designs.
- The app's brief prompt (`SYSTEM_PROMPT` in `src/lib/brief.js`) was written by Claude.

## Checks done on the AI-generated code

- Unit tests for the scoring formula, reason lines, Who's Blocked list and the citation-or-drop guardrail (`npm test`).
- A browser test of every action (Done + Undo, Snooze, Assign, search, demo states) and of the AI path against a mocked API, including a deliberately unsourced sentence that the guardrail removed.
- An axe-core accessibility audit of every page (no violations).
- Bugs found and fixed during testing: the brief could get stuck on a blank card at load; filter buttons were announced as "Snoozed1" instead of "Snoozed 1"; names were lower-cased in the rule-based brief.
