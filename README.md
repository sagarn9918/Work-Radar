# WorkRadar — MVP

One ranked, explained view of a manager's day across Slack, Jira, GitHub and Email.
Built for a Product Management course assignment. **All data is invented mock data.**

![Dashboard](docs/screenshots/dashboard.png)

## Run it

Needs [Node.js](https://nodejs.org) 20 or newer.

```bash
npm install
npm run dev      # opens on http://localhost:5173
```

Other commands: `npm test` (scoring and guardrail tests), `npm run build` (production build into `dist/`), `npm run preview` (serve the build).

| F8 · Empty and error states | Settings → Demo states (Jira down, AI fails, empty feed) |

## How the AI is used

- **Ranking is not AI.** Every item is scored with the PRD formula (Appendix A2):
  `P = 30·Blocking + 25·Wait + 25·Deadline + 20·NeedsMe`. Urgent ≥ 70, Today 40–69, Later < 40.
  The reason line is built from the same factors, so it always matches the score.
- **The daily brief can be written by Claude.** Add an Anthropic API key in **Settings**. The app sends the day's
  ranked items to Claude (`claude-haiku-5-5` by default) and asks for four sections in JSON, each sentence citing item ids.
- **Guardrail: citation or drop.** Any sentence whose sources are missing or not real item ids is removed before display,
  and the brief says how many lines were removed (`validateBrief` in `src/lib/brief.js`).
- **No key? Still works.** Without a key the brief is generated by rules from the same data and is labelled
  "Rule-based · no AI key added". If the API call fails, the feed keeps working and the brief offers "Try again" or the rule-based version.

> The API key is stored only in your browser's local storage and sent only to `api.anthropic.com`.
> That is fine for a local demo; a production build would keep the key on a server.

## Project structure

```
src/
  data/mockData.json      all mock data (people, items, events) — clearly marked as invented
  lib/scoring.js          priority formula and bands (PRD Appendix A2)
  lib/reasons.js          reason lines and the Who's Blocked list
  lib/brief.js            AI brief, rule-based fallback, citation-or-drop guardrail
  lib/logic.test.js       unit tests (node --test)
  store.jsx               app state: actions, undo toast, brief generation, demo states
  components/             layout, feed row, actions, brief card, blocked list, icons
  pages/                  Today, Priority Feed, Who's Blocked, Item detail, Search, Settings
```

## Accessibility

Checked with axe-core (WCAG 2.1 A/AA rules plus best practices): no violations on any page.
Text contrast is 7:1 or higher. Priority is always shown as a word and a number, never colour alone.
All controls are native buttons, links, selects and inputs with 44 px targets. Skip link, visible focus ring,
focus moves to the page heading on navigation, actions are announced through a live region, and motion
respects the reduced-motion setting.

## Known limits (by design for the MVP)

- Mock data only; no live integrations or sign-in.
- Actions stay inside WorkRadar and are not written back to Jira or Slack.
- The mock clock is fixed at Thursday, 15 October, 9:04 AM so scores are reproducible.
- "Open in GitHub/Jira/…" links go to each tool's home page, since the items are not real.
